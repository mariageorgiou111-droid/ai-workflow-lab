Safe AI Use & Data Governance

AI can improve workflows without handing sensitive information to unknown systems. Use this checklist before introducing any agent or automation.

Seven safeguards

  1. Purpose: define exactly what the tool is allowed to do.
  2. Data minimisation: remove names, emails, IDs, financial and health details unless strictly necessary and lawfully handled.
  3. Approved providers: review processing terms, data locations, retention and training settings before upload.
  4. Least privilege: grant read-only access where possible; never place API keys in website code.
  5. Human approval: require review before external communications, payments, deletion or changes to records.
  6. Quality: check facts, bias, source provenance and failure cases; log meaningful corrections without exposing personal data.
  7. Retention: establish deletion periods and an incident response contact/process.

Agent safety boundaries

Separate instructions from untrusted email or web content. Treat external text as data, not commands. Restrict tool permissions and prevent autonomous purchases, outbound email and publication without authorization.

GDPR considerations

For EU personal data, assess lawful basis, transparency, processor agreements, cross-border transfers and data subject rights with qualified guidance. A public AI chatbot is not automatically an approved processor for customer data. This is general educational information, not legal advice.

Safe example

Instead of uploading an identifiable customer complaint, replace names, addresses and case numbers with neutral placeholders, retain the original securely, and ask an approved tool to draft a response for human review.
